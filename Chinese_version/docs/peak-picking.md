# 选峰与定位

选峰在最终处理谱上检测局部峰顶，精修坐标并写出峰表；它不修改谱图，也不完成蛋白指认。
本页描述当前源码。旧峰表不会自动改写，更新检测规则后需重新选峰。

## 检测与强度口径

`workflow/pick_peaks.py::pick_peaks` 写出 POKY 风格 `.list`、逐峰定位附件和运行记录。

| 参数 | 含义 |
| --- | --- |
| `sigma_multiplier` | 噪声倍数阈值，默认 35σ；实际值及来源留档。 |
| `edge_margin_ppm` | 显式人工排除边距，单位 ppm；默认不设置无条件边带遮罩。 |
| `edge_margin_points` | 显式人工点数边距；填零改变点距，不宜用于跨分辨率比较。 |
| `localization_method` | 仅接受 `parabolic`；不支持的方法会明确报错。 |
| `ref_peaks`、`ref_nuclei`、`tolerance_ppm` | 可选参考峰表约束，见下节。 |

噪声使用稳健估计，阈值、峰高与 S/N 相对谱数组的全局中位数背景；这只是度量口径，
不是空间变化的基线校正。非有限谱值拒绝选峰，不会静默返回空表。
半格点造成的紧凑等高峰顶合并为一个候选；长脊与宽平台不当作真实局部峰顶。

### 轴峰筛查

自动筛查先核对实验类型、核组合和采集参数；仅在先验允许时检查最终谱的原始边缘。
实际排除还需要大量、窄、分散且对齐的候选峰证据，不能凭“有峰靠近边缘”就删除。
少量孤立边缘峰、内部载频峰、未知类型、参数冲突或无法确认的裁剪边界均保留。
该规则是启发式筛查，不证明某个峰一定是伪影；判据、排除数和未筛查原因会留档。
GUI 选峰、SMILE 评估与 API 组合复用同一判据。显式边距属于人工覆盖，报告与自动筛查分开记录。

### 峰的符号

自动模式依据实验模板；相敏 COSY、NOESY/ROESY 等 mixed 模板保留正负候选。
未知或低置信度类型可用强双符号证据兜底，不强制只保留多数符号。
API 显式指定 `positive`、`negative`、`both` 或 `dominant` 时按请求执行，并记录来源。
这里的“同号/mixed”是峰符号，不是 uniform/NUS 采样类型。

`dominant` 比较正负候选的信噪比平方和 `Σ(SNR²)`，不再由候选数量决定。这使大量弱反号杂峰不会轻易压过较少的强主信号；权重相同时优先正峰，真正负峰主导的谱仍可识别。
正常自动处理的单符号谱预期为正峰。未知类型只有两侧均有至少3个候选、较弱侧权重达到较强侧的20%，且两侧都不是单个极强峰支撑时才自动保留双符号。检测记录的 `sign_evidence` 保存两侧候选数、归一化权重、权重占比及主符号。


## 参考峰表约束与“对齐参考”

对齐参考估计当前峰表与参考峰表之间的整体化学位移偏移，用于容差内匹配；
它不移动谱图、不改变处理参数，也不是谱图相似性或指认正确性的证明。

- 共有轴按核种和逻辑 F 轴身份匹配；同核轴不能互换，重复核坐标需保留 `核名:F轴` 身份。
- 对齐可靠时，参考约束只保留匹配候选。2D 参考约束 3D 时，未共有的第三维自由，
  因此一个参考峰可以保留多个三维峰；这不是一对一指认。
- 无共有坐标、轴身份歧义或对齐质量低于门槛（当前 60%）时跳过自动过滤，保留候选并提示原因。
- 参考少于 5 峰时不估计全局对齐，直接用原始坐标匹配；非有限坐标或非法容差明确失败。

“对齐后导出”另行对输出峰表施加整体偏移；同样不修改源谱图。请核对参考是否来自可比较条件。

## 三点抛物线定位

逐轴使用局部三点抛物线估计亚格点顶点，适用于 2D/3D；界面不再提供定位方法选择。
抛物线是确定性闭式解，没有迭代收敛或高斯拟合预算。

定位记录里的 `success` 与峰表的 `fit_success` 含义不同：前者表示定位已执行，
后者表示有限等效线宽可计算；贴边或非凹三点模板可能没有有效线宽。
`boundary_hit` 表示顶点偏移达到 ±0.5 点边界。等效线宽是局部曲率估计，不替代完整线形拟合。
`fallback` / `fallback_reason` 保留为兼容字段，不虚报算法切换。

附件 `<峰表>.localization.json` 保存请求/实际方法与逐峰记录；运行参数也保留定位信息。
旧接口的 `gaussian` / `both` 请求明确报错，不静默回退。

## 峰表与使用

峰表列保留逻辑 F 轴坐标、核标签与单位，轴身份按 NMRPipe `FDDIMORDER` 解释，
不按核名猜存储顺序。空 3D 峰表仍保留三维化学位移表头。

GUI：生成谱图后运行“峰挑选”，点峰表行可定位谱图。Python：

```python
from workflow.pick_peaks import pick_peaks

result = pick_peaks(manager, "exp_001", "data_001", sigma_multiplier=35)
print(result["peak_count"], result["peak_path"])
```

API 见 [接口参考](external-api/03-api-reference.md)。解析/导出已有峰表不需要 NMRPipe；
从原始数据生成处理谱需要外部引擎。发表时请明确阈值、符号模式、人工边距、参考约束和软件版本。

## 噪音与信噪比

选峰以谱实部的全局中位数 `b` 为基线，噪音为 `sigma = 1.4826 × median(abs(data - b))`（MAD）；换算后的 sigma 小于 `1e-12` 时改用全局标准差。峰高为候选网格点的 `data - b`，`SNR = abs(峰高) / sigma`，噪音为零时记为 0。三点抛物线仅精修坐标，不改峰高或 SNR。GUI 的 SNR 保留一位小数，使用本次选峰的噪音，不在加载峰表时重估。

项目内部自动保存的POKY/Sparky `.list` 有有效SNR时可带 `S/N` 列；界面的直接/对齐后导出关闭指标，只写指认和ppm。内部表没有有效SNR时保持原表头。同表缺值写作 `nan`，导入后显示空白；同时兼容 `SNR`、`SN` 列名。选峰附件 `.localization.json` 保存逐峰完整精度 SNR、峰高以及运行的 `noise_sigma` 和 `baseline_offset`。旧表没有 SNR 时需重新选峰才能得到本程序的信噪比。

这与 POKY 的噪音口径不同：[官方 iPick 选峰入口](https://github.com/pokynmr/iPick/blob/master/iPick.py)抽取100个随机点，[ucsfTool实现](https://github.com/pokynmr/iPick/blob/master/ucsftool3.py)取绝对强度排序的中间值；[峰表代码](https://github.com/pokynmr/iPick/blob/master/peak_list_dialog.py)以峰高除以谱的noise，并标记为S/N。本程序保留既有MAD算法与阈值，导出列兼容不表示计算值相同。

界面“导出峰表”的直接导出和对齐后导出仅写 `Assignment w1 w2 [w3]`，不写 Data、Height/Intensity、Volume 或 SNR。界面峰表和项目内部保存仍保留强度与 SNR；导出文件用于指认/坐标交换，重新导入时不会补造 SNR。

## POKY/iPick 兼容性证据

**核心机制相近、本批输出高度一致。** NMRFinesse二维正峰选峰采用阈值约束的邻域局部极大值检测，再逐轴三点抛物线细化，与本次POKY/iPick UCSFtool路线核心机制相近。
12张保留的¹H–¹⁵N谱形成24组高/低阈值比较，全部候选数一致，5175条表内候选记录在逐轴一个网格步范围内唯一一一对应。weak/A两档相同的4表复用，实际独立有效iPick调用20次；5175不是独立物理峰数。
坐标差典型约0.00025 ppm、最大约0.00050 ppm，与iPick三位小数输出量级相符。下游可用性8088格中8084格一致，4格来自同一成员/运行在四控制中的重复；此统计区别于候选峰配对。
该证据采用传输修正后的ipick_transfer_v2，原协议的历史API版本为1.0.8/API1.1.4，后续诊断和机制核对为1.0.9/API1.1.5。它是历史表级复核，不重标为当前发行版输出，也不证明整个POKY/SPARKY实现、3D/负峰/平台峰或峰身份完全等价。
阈值须换算：API去中位数后的T×1.4826×MAD，对应iPick原谱绝对阈值median+T×1.4826×MAD；本项目现有噪音/阈值算法不因引用证据而改变。
私有原包CSV与manifest保持原样；公开版CSV不变、来源元数据脱敏并记录原文件哈希，见[使用说明](../../docs/evidence/picker-ipick-v1/README.md)、[表级核验输出](../../docs/evidence/picker-ipick-v1/verification.txt)与[兼容性核验](picker-compatibility.md)。原始谱/FID和第三方源码不在证据包中。
